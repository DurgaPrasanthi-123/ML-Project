End-to-End System Pipeline

How The System Works

Follow the complete step-by-step workflow: from user input and offline feature extraction to machine learning inference and risk scoring.

1

Step 1: User Enters Website URL

The user inputs a target URL on the web client interface (e.g. https://www.paypal.com or http://192.168.1.1/login.php). The client-side JavaScript checks that the field is non-empty and initiates an asynchronous fetch() request to the Flask backend.

2

Step 2: URL Sanitization & Syntax Validation

The Flask REST API receives the JSON payload. Before running ML algorithms, the server validates the string length, strips whitespace, inspects protocols (rejecting harmful schemes like javascript: or data:), and parses the URL into standard components using Python's urllib.parse.

3

Step 3: Passive Feature Extraction (17 Numerical Features)

The URL is transformed into an ordered 17-dimensional numerical feature vector. The system strictly inspects lexical and structural indicators—never establishing an outbound connection to the host. This guarantees zero exposure to malware or web exploit payloads.

4

Step 4: Machine Learning Inference

The feature vector is fed into the serialized Random Forest Classifier (phishing_model.pkl). 120 independent decision trees analyze the feature combinations and cast votes. The model computes both the binary classification and the posterior probability distribution.

5

Step 5: Probability Calibration & Risk Categorization

The prediction is categorized into Legitimate (Class 0) or Phishing (Class 1). A confidence percentage is generated (e.g., 98.4%). Risk levels are assigned as Low, Medium, or High, and specific risk explanations are attached to the response payload.

6

Step 6: Frontend Dynamic Result Display

The client receives the JSON response and immediately updates the UI without reloading the page: displaying a clear status verdict (✓ Legitimate Website or ⚠ Potential Phishing Website), confidence percentage, and an itemized breakdown of threat indicators.

Why These Features Matter

Phishing actors employ predictable evasion and deception strategies. Here is how our 17 features detect those tactics:

🔢

IP Address as Hostname

Legitimate services almost exclusively use registered domain names. Attackers often deploy phishing servers on raw IP addresses (e.g. http://45.142.214.12/login) to bypass domain registration fees or DNS reputation filters.

➖

Hyphen Count & Typosquatting

Legitimate domains rarely contain multiple consecutive hyphens. Phishers use hyphens to construct deceptive domains that look like trusted brands (e.g., paypal-secure-verification-center.com).

🌐

Excessive Subdomains

Attackers frequently stack multiple subdomains (e.g., login.paypal.com.account-update.xyz) to fool mobile browsers with truncated URL address bars into displaying the legitimate brand name.

🔑

Sensitive Security Keywords

Phishing pages almost universally target sensitive credential harvesting. The presence of words like login, verify, banking, update, confirm, wallet in non-standard domain contexts signals high risk.

🔒

HTTPS Transport Layer

Modern reputable websites enforce HTTPS encryption. Although modern phishers also obtain free SSL certificates, a website requesting login credentials over plain HTTP is an immediate critical red flag.

✂️

URL Shorteners & Redirection

Shortening services (e.g., Bitly, TinyURL) conceal the true host. Similarly, multiple slashes (//) inside path tokens are often leveraged in open-redirection attacks.
